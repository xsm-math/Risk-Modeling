# 简历表述与面试提纲

## 项目名称

**信用违约预测与成本敏感风控策略（个人项目，模拟数据）**

技术栈：Python、NumPy、pandas、WOE/IV、逻辑回归、评分卡、PSI、pytest、GitHub Actions。

## 可用于简历的三条描述

- 基于 8,000 条模拟信贷样本，构建数据清洗、分层切分、WOE/IV 筛选与 L2 逻辑回归流水线；保留 8 项特征，测试集 AUC 0.7339、KS 0.3645。
- 根据误拒/误放成本假设，在验证集选择决策阈值；测试集离线成本相较 0.5 阈值降低 17.80%，同时报告通过率与违约召回率，分析成本和风险识别之间的取舍。
- 实现评分卡转换、特征/分数 PSI 监控和收入漂移告警；通过 22 项自动化测试，覆盖评分卡一致性、拟合范围、分箱映射及指标数值校验。

这些描述用于已阅读、复现并能够解释实现之后。不要将模拟成本降低写成真实业务降损，不要将当前基线写成已上线系统；也不应把协助生成的代码描述成独立完成的全部工作。

## 60 秒项目介绍

这是一个模拟信贷数据上的信用风险建模实验。我关注的不只是 AUC，还包括评估流程和决策成本。
数据切分后，中位数、分箱、WOE 和模型只在拟合集学习，验证集负责选阈值，最后报告测试表现。
在每个误拒损失 400 元、误放损失 8,200 元的假设下，选择的阈值约为 0.0363，测试成本比 0.5 阈值低 17.80%。
我还检查了标准化系数到评分卡的换算，并用收入乘 1.3 的实验验证 PSI 告警。
目前主要限制是模拟数据和历史参数选择偏差，下一步需要真实数据与独立验证。

## 必须能解释的问题

1. **为什么 WOE 只能在拟合集上拟合？** WOE 使用标签计算好坏比例；让验证标签参与会污染后续阈值选择。
2. **为什么不按 0.5 拒绝？** 决策取决于代价与概率校准。校准理想时，该成本矩阵的理论阈值为 400/(400+8200)≈0.0465；有限验证样本上的网格最优值不必相同。
3. **17.80% 是什么？** 同一测试集、同一假设成本矩阵下，相对 0.5 阈值的经验成本变化，不是真实收益，也不保证迁移到未来数据。
4. **标准化后怎样做评分卡？** w_raw=w_std/σ，b_raw=b_std−μ·w_raw；否则 WOE 到分数的解释会与预测不一致。
5. **PSI 小是否等于模型有效？** 否。它只测分布变化，需要结合成熟标签上的 AUC、KS、校准和损失判断。
6. **历史测试集参与选参如何处理？** 明确披露；修复泄漏不等于恢复历史独立性，需要新数据或独立留出集。
7. **评分卡为什么有负贡献？** 本项目 WOE 取 ln(bad%/good%)，违约 logit 越大分数越低。符号约定必须与公式保持一致。
