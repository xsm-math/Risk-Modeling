# 信用风控项目面试讲义

本讲义与真实运行结果同步。建议先自己复现、检查结果表，再使用下面的讲法。
这是公开数据上的个人应用研究，不是银行生产项目。历史测试划分已公开，
本次为扩展实验，不能声称获得了全新独立外部验证。

## 1 分钟介绍

我做的是信用卡客户下一月违约风险建模，使用 UCI 的三万条历史记录。
重点是把风险排序、概率质量和决策成本一起评估。我先检查缺失、异常编码
和重复金融记录，按重复记录分组，拆成训练、校准、验证和测试四部分。
然后实现 WOE/IV 与 Logistic 评分卡，对比 Random Forest、XGBoost 等模型。
验证集选出的 random_forest_sigmoid 在测试集 AUC 为 0.7917、KS 为 0.4580。
我还核对了评分卡分数到概率的还原、SQL 与 Python 特征一致性，并分析校准、
成本阈值和 PSI。成本只是明确假设下的离线比较，数据也不支持真正 OOT；
项目的价值是完整且可检查的研究流程。

## 3 分钟介绍

这个项目研究既有信用卡客户在观察期结束后的下一月违约概率。
数据来自 UCI，共三万条，违约占比 22.12%，包含六期还款状态、账单和付款。
我没有把它描述成新客审批模型，因为样本中没有被拒申请人，也没有实际损失。

第一步是建立数据和验证边界。文件校验 SHA256，检查缺失、极端值、类别编码
与重复输入。负账单和高利用率可能有业务含义，因此只标记，不随意删除。
相同金融记录必须分到同一组，哪怕标签冲突也保留。四部分划分约为六成训练、
一成校准、一成验证和两成测试，所有需要学习的步骤都限定在相应集合。

方法上，一条路线是传统评分卡：训练集分箱、计算 WOE/IV，再拟合 Logistic。
我把标准化系数还原，按 600 分、好坏比 20:1、PDO 20 转成逐箱分数，并验证
分数能还原原模型概率。另一条路线是原始特征 Logistic、Random Forest、XGBoost
和原有的直方图 GBDT。加权 Logistic 是不平衡处理的对照；校准单独拟合，
避免把训练内预测拿去校准。

选型依据是验证 Log loss，测试只报告冻结后的结果。主模型是 random_forest_sigmoid，
AUC 0.7917、KS 0.4580、AP 0.5700、Brier 0.1322。我没有只报告 AUC，
还分析 PR、可靠性曲线、分箱人数以及不同阈值的 Precision、Recall 和 F1。
在误拒成本 1、漏放违约成本 5 的情景中，验证阈值 0.171438，测试通过率
56.64%、违约召回率 75.41%、每客户归一化成本 0.5387。
比较 WOE 的成本与置信区间后才能判断是否支持更优决策，不能由 AUC 推出收益。

工程上我做了固定配置、一键运行、SQL 六期聚合及全量一致性检查，导出模型
并校验加载后的预测。解释包括 WOE 点数、置换重要性和 XGBoost TreeSHAP。
稳定性分析是同群体 PSI 加人工场景压力测试，明确没有把客户 ID 当时间。
下一步最有价值的是取得近期多期快照，做真正 OOT 和成熟标签监控。

## 5 分钟介绍

我的出发点是：信用风控模型不仅要把坏客户排前，还要给出可信的违约概率，
并能解释这个概率如何影响决策。因此我在已有评分卡仓库上继续迭代，保留原
NumPy 模拟实验，另外扩展真实公开数据的研究流程，没有把两种数据的指标混用。

数据是 UCI 的三万条既有信用卡客户记录，六期状态、账单和付款来自 2005 年，
目标是下一月违约。这意味着预测时点必须设在观察窗口结束后；数据不包含
不同客户的快照截止日期、真实违约敞口或拒贷样本。这个边界决定我不能声称
完成新客审批验证、真正 OOT 或人民币收益评估。

数据检查上，我审计缺失和非有限值、类别编码、分位数、IQR 标记、重复输入
和冲突标签。负账单可能代表贷方余额，利用率超过一也不必然是错误，所以保留。
状态 -2 和 0 的资料说明不完整，我保留原码并写明限制。ID 和人口属性不入模，
但排除人口属性不能保证消除代理偏差。相同金融记录以整组方式分配到四个集合，
冲突标签也不按结果去重，避免通过删除难样本虚增指标。

实验分工是训练约六成，校准、验证各一成，测试两成。训练学习中位数、分箱、
WOE、标准化和模型；校准集拟合 sigmoid；验证集按 Log loss 选模型及概率版本，
并选择成本阈值；配置先写出，再获得测试预测。所有容量固定，没有通过测试
挑参数。这里也有局限：验证集同时服务模型和阈值选择，会有选择乐观偏差；
历史测试结果此前已公开，本次是同一公开划分的扩展，不是全新独立证据。

评分卡路线里，WOE 使用坏样本占比除好样本占比的对数，符号约定和另一种
常见定义相反，需要与系数一起解释。IV 衡量单变量分箱的区分信息，我导出
IV 而没有按测试效果删特征。相邻稀疏箱会合并，但现有编码器停止于两箱，
不能声称每箱都满足最少坏样本数；它也没有单调性约束。Logistic 的标准化
参数还原到 WOE 单位，再映射成分数。基准好坏比 20:1 对应 600 分，PDO 为 20，
好坏比翻倍就多 20 分。最终验证每箱点数相加能还原原始 WOE 模型概率。

机器学习路线比较原始 Logistic、加权 Logistic、Random Forest、XGBoost
和历史 GBDT。每个模型都有独立校准版本，因此不是只比较最有利的那一行。
选择 random_forest_sigmoid 的依据来自验证集。其测试 AUC 为 0.7917、KS 0.4580、
AP 0.5700、Brier 0.1322。排序之外，我检查平均预测 PD 与实际违约率、
可靠性曲线每箱人数，以及校准是否真的改善概率损失。加权会改变概率水平，
因此不能直接把加权分类器输出当真实违约率。

决策采用明确的损失函数：误拒正常客户成本为 1，放行违约客户成本为 5。
如果概率准确，比较批准的 5p 和拒绝的 1-p，理论阈值就是 1/6。
经验阈值则从验证集所有可达的同分边界选择，并纳入全通过和全拒绝。
本次阈值 0.171438，测试通过率 56.64%，违约捕获率 75.41%，
成本 0.5387，WOE 对照成本 0.5600。我保留其他成本比和 0.5 阈值结果，
并给出分组配对 bootstrap 区间。若成本差区间包含零，就不能宣称有可靠收益改善。

解释层面，评分卡给出逐箱贡献，树模型给出验证集置换重要性、树内重要性
和 XGBoost 原生 TreeSHAP。SHAP 的加和校验在原始 log odds 空间做，不能把它
误当作校准后 PD 的加法分解，更不能说某特征造成了违约。
监控层面，PSI 使用训练固定箱，比较正常测试样本和额度/还款状态扰动场景，
所有依赖特征重新计算。这是压力测试，没有新的真标签，不能报告模拟 OOT AUC。

工程上，SQL 用真实六期记录构成长表，以 CTE、CASE 和窗口函数做近三期、
六期聚合；五项共享特征在全部记录上与 Python 核对。原始数据与逐客预测只
留本地，仓库提交汇总表、图、版本和哈希。一键运行会重新生成报告及数字。
项目现在最能展示的是数学公式、实验隔离、业务阈值与实现验证之间的连接。
后续我会优先补近期多期数据、特征可用时点和成熟标签，而不是继续对公开
测试集堆模型。

## 核心公式与业务含义

| 公式 | 含义与本项目口径 |
|---|---|
| `p=1/(1+exp(-z)), z=b+Σβ_j WOE_j` | 条件违约概率；正类为违约 |
| `WOE=ln(bad_share/good_share)` | 本项目正 WOE 表示该箱相对更偏坏；另一符号约定也可用 |
| `IV=Σ(bad_share-good_share)×WOE` | 单特征的分箱区分信息，不是联合模型贡献 |
| `odds_good_bad=(1-p)/p` | 好坏比；p=1/21 对应 20:1 |
| `factor=PDO/ln2, score=base_score+factor×ln(odds/base_odds)` | 基准分和好坏比，概率变小分数变大 |
| `KS=max(TPR-FPR)` | 在同一阈值处坏样本与好样本累积分布的最大距离 |
| `Brier=mean((p-y)^2)` | 概率平方损失，同时反映校准和区分能力 |
| `PSI=Σ(q_k-p_k)ln(q_k/p_k)` | 参考与当前分布距离；箱和预处理必须固定 |
| `cost=C_FP×FP+C_FN×FN` | 本实验已知标签上的离线核算，不是实际现金收益 |
| `threshold=C_FP/(C_FP+C_FN)` | 比较拒绝的 C_FP(1-p) 与放行的 C_FN p，要求成本模型成立 |
| `EL=PD×LGD×EAD` | 真正违约损失估计需要敞口与损失率；本数据不支持金额估计 |

## 36 个深挖问题与参考答案

### 1. 你的研究问题是什么？
预测已有信用卡客户在六期信息齐备后的下一月违约，比较排序、概率和假设决策成本。
不是新客审批因果模型；样本选择范围与预测时点决定结论边界。

### 2. 为什么保留原项目而不是重新做？
原实现有 NumPy Logistic、WOE 和阈值检查，可以继续作为数值与模拟基线。
真实数据路线复用可验证模块，扩展基模型、诊断和推理；两种数据的结果分别报告。

### 3. 缺失值怎么处理？
先审计，本次 UCI 文件缺失为零。原始 LR 的中位数与 WOE 的填充值只学训练集。
不能宣称已证明缺失机制下的鲁棒性；后续可比较缺失箱/指示变量并做缺失压力实验。

### 4. 哪些异常值不能直接删？
负账单、超额度利用率和极端付款有可能是真实行为。IQR 只是标记，不能代替业务规则。
状态 -2/0、教育和婚姻异常编码也保留并说明；需向数据方核实含义，而非按标签改码。

### 5. 为什么按重复金融记录分组？
同样模型输入跨训练和测试会使验证过于乐观。按 19 个账户字段哈希整组分配，
包括不同 ID 和冲突标签；不按结果去重。哈希分组仍不解决隐藏实体关系或时间依赖。

### 6. 四个集合分别做什么？
训练学处理规则和估计器，校准只学概率映射，验证选模型与阈值，测试报告冻结结果。
校准标签不能重训基础模型，测试标签不能选择模型或损失比；这些边界有测试和运行记录。

### 7. 测试集是否从未被看过？
不是。原仓库已公开该划分的结果，本次明确是扩展。代码仍把本次选型限制在验证集，
但研究层面不能重新赋予测试集“全新独立”地位。需要新的外部或后续时期数据。

### 8. 为什么用 WOE？
把不同数值箱映射到相对好坏占比，便于拟合和输出每箱风险贡献，也能表达分段非线性。
它是有监督变换，必须训练内拟合；稀疏箱、零频数和重复使用标签可能造成不稳定。

### 9. WOE 符号如何解释？
本项目是 ln(坏占比/好占比)，正值意味着该箱更集中坏样本。若 β 为正，WOE 增大
提高 log odds；若其他特征相关，条件系数可能改变符号。不能脱离符号约定解释系数。

### 10. IV 越高一定越好吗？
不是。IV 是训练内单变量度量，高值可能是泄漏、极小箱或业务定义近似标签。
0.02、0.1、0.3 等只是常见筛选经验，不是显著性标准；本真实数据路线不据此删变量。

### 11. 分箱满足单调性吗？
没有强制单调。本实现量化分箱并合并相邻稀疏箱；停止于两箱时可能仍未满足最少坏样本数。
如果业务要求方向一致，应在训练内加入单调约束，再独立比较预测与稳定性损失。

### 12. 如何防止 WOE 泄漏？
每个箱的边界和好坏比例只由训练数据获得，其他集合只应用固定映射。
未来若增加交叉验证，WOE 必须每折重新拟合，不能先用全数据编码后再做 CV。

### 13. Logistic 为什么仍常用于风控？
它输出简单可版本化的条件概率，WOE 后能转为加法分数和原因贡献，维护成本较低。
这是工程和解释上的优点，不是永远比树更准，也不意味着天然满足监管要求。

### 14. Logistic 的系数是什么？
保持其他输入不变，某 WOE 增加一单位，违约 log odds 改变 β、违约 odds 乘 exp(β)。
本项目先除以标准化尺度并调整截距；未还原的标准化系数不能直接进入逐箱评分公式。

### 15. Base score、odds、PDO 有什么区别？
Base score 是参考点，base odds 是这个点对应的好坏比，PDO 决定翻倍好坏比的分差。
本项目 600 分对应 20:1，40:1 对应 620 分；改变映射并不改变模型风险排序。

### 16. 评分卡与校准模型是否同一个？
评分卡导出的是未校准 WOE LR 的精确加法映射，单独校准版本是另一个概率模型。
sigmoid 对原 logit 的线性映射理论上可以重新映射分数，但本实现不会把两者悄悄混用。

### 17. KS 是什么？
模型阈值从低到高移动时，分别计算坏客户捕获率和好客户误拒率，取 TPR-FPR 最大值。
它衡量最强分离位置。最大 KS 阈值不等于业务成本最优阈值，测试 KS 也不能用于选审批线。

### 18. AUC 与 KS 有什么区别？
AUC 汇总整条 ROC，等价于随机坏客户比随机好客户得分高的概率（平分计半）。
KS 只取曲线离对角线的最大垂直距离。它们可排序不同，也都不评价绝对 PD 是否准确。

### 19. PR-AUC 为什么有两列？
Average precision 用精度乘召回增量，梯形 PR-AUC 使用线性插值，两种定义不完全一样。
不平衡下 PR 对误报更敏感，AP 基准与正类占比有关，跨群体比较时必须报告坏样本率。

### 20. 为什么不能只报准确率或 F1？
准确率可能被多数类主导；F1 忽略 TN，也没有表达实际 FP/FN 损失。
我把 F1 与阈值、混淆矩阵一同报告，模型概率质量用 Brier/Log loss，策略则用明确成本。

### 21. 类别不平衡怎么处理？
主策略是保留人口比例、学习概率并用成本阈值。另有 balanced LR 和 RF 加权对照。
没有盲目 SMOTE；该数据坏样本约两成，能直接学习。是否加权由验证概率损失决定，
不因少数类就自动重加权；加权后需检查概率偏差并独立校准。

### 22. 为什么 XGBoost 没用负正比例作为权重？
我优先估计概率，scale_pos_weight 固定为 1。放大正类权重可提高某些阈值的召回，
但可能把输出向高概率推移。成本可以在预测后处理；加权的收益需要独立验证而非默认成立。

### 23. 为什么要校准？
当决策使用概率和成本时，“0.2 风险”应在相似预测群体中对应约 20% 违约。
排序好并不保证这一点。校准在独立集拟合 sigmoid，评估曲线、平均 PD 与概率损失。

### 24. Brier 降低就证明校准变好了吗？
不能。Brier 同时包含可靠性、分辨率和数据不确定性。应与可靠性曲线、样本数、
Log loss 和平均预测概率一起看；我保留所有校准前后结果，不把负结果删除。

### 25. 为什么选 sigmoid 而不是 isotonic？
sigmoid 参数少，在约三千条校准数据上有更稳定的方差；isotonic 更灵活但会产生平台和稀疏区过拟合。
这是预设方案，不是证明 sigmoid 总优。若比较方法，应只在验证集选择，测试不参与。

### 26. 阈值如何结合损失？
误拒好客户 C_FP，放行坏客户 C_FN。拒绝的条件期望是 C_FP(1-p)，批准是 C_FN p，
比较得到 p≥C_FP/(C_FP+C_FN)。模型概率、成本和简化假设成立时才可用这个规则。

### 27. 经验阈值和理论阈值为何不同？
经验阈值最小化有限验证样本的已知标签成本，会受抽样、校准误差和模型误差影响。
理论阈值来自期望损失。本次两者与 0.5 都报告，不能依据测试结果选哪个对外讲。

### 28. 相同分数怎么处理？
在整个同分块边界搜索，不把相同分数的人拆开制造不可实现策略。
包含全部通过和全部拒绝，成本相同时选更少拒绝。通过率目标也允许因同分而偏离。

### 29. 为什么不能用信用额度当 EAD？
额度只是上限或授信信息，不等于违约时余额，也没有回收率和 LGD。
真正金额 EL=PD×LGD×EAD，需要合同敞口与违约回收数据；当前只报告归一化错误成本。

### 30. PSI 如何解释？
PSI 比较固定箱内的占比变化，接近零说明这项边际分布相似，较高时触发检查。
0.1/0.25 是经验门槛，不是 p 值。必须结合样本量、分箱、缺失、季节与业务变化；
标签条件分布变化可能在 PSI 很小的时候发生。

### 31. 做了真正 OOT 吗？
没有。每条记录都覆盖同一组月份，没有多期客户快照。按 ID 排序不是时间切分。
人工减额度/加逾期状态只是敏感性压力场景，没有新真标签，不能声称模拟获得 OOT 性能。

### 32. Scorecard vs LightGBM/XGBoost 怎么选？
评分卡适合透明的加法规则和轻量部署；boosting 擅长非线性与交互，但运行与解释更复杂。
本项目实际使用 XGBoost，不把 sklearn HistGBDT 称为 LightGBM。选择应综合概率、成本、
监控和维护要求，不能只看测试 AUC，也不能用“可解释”替代合规审查。

### 33. SHAP 或 feature importance 说明因果吗？
不说明。树内 gain/impurity 会偏向某些分裂；置换受相关变量替代和不自然组合影响。
TreeSHAP 在原始 XGBoost log odds 上检查加和，校准后概率没有直接同样的加法分解。
它解释模型分配，不能说还款某字段的改变必然导致违约改变。

### 34. Bootstrap 区间涵盖所有不确定性吗？
没有。测试集重复金融组整组重采样，两模型共享抽样以比较差值，但模型和阈值已经固定。
它不覆盖重新训练、再次选型、不同经济时期和外部数据偏差。成本差区间跨零时不能宣称稳定降低成本。

### 35. SQL 做了什么，怎么证明没错？
从实际六期字段构成长表，以窗口函数定 recency，以条件聚合算近三期和六期行为。
五项共享特征在三万条上与 Python 核对，并测试最新三期顺序、负账单和分母规则。
账户年龄因缺开户日期而不构造；真实生产还应按观测时点限制事件和入库时间。

### 36. 模型上线怎么监控，拒绝推断如何推进？
输入层监控 schema、缺失、未知码和特征时点；输出层看 PD/评分、通过率、额度和 PSI。
成熟标签到齐后分月份/人群看 AUC、KS、PR、校准和实际损失，记录延迟与选择偏差，
必要时重新校准、回滚或重训。拒贷人没有标签，不能用模型预测冒充真值；
拒绝推断需明确可识别性假设、验证偏差和合法获得代表性结果的机制，当前仅讨论限制。

## 上线前后的讲解框架

本仓库实现本地批量推理和诊断，不声称线上部署。真正落地至少需要版本化输入、
观测时点/入库时点审计、模型与阈值共同发布、影子评估、异常兜底和回滚。
早期无标签监控只发现输入/输出变化；有成熟结果后才能评估表现、校准与损失。
不能看到 PSI 告警就直接重训，也不能在审批改变样本构成后按旧指标解释新数据。
